1. QUÉ SE HIZO
-------------

Se integró Kapso (WhatsApp Cloud API) en el CRM con el camino más pequeño posible:

- Un botón "WhatsApp" en la tabla de contactos.
- Un modal para escribir y enviar el mensaje.
- Una ruta autenticada: POST /api/whatsapp/send
- Un helper de servidor para hablar con Kapso.
- Un script de consola para probar credenciales y envío.
- Variables de entorno documentadas.

No se agregó una bandeja de entrada completa ni webhooks.
No se modificó el comportamiento de propiedades, ofertas u oportunidades.

3. ARCHIVOS NUEVOS
------------------

- src/lib/kapso.ts
  Helper del servidor. Exporta:
  - sendWhatsAppText(to, text)
  - normalizeWhatsAppRecipient(value)
  - kapsoConfigured()
  - kapsoPhoneNumberId()
  - KapsoError

  Endpoint usado:
  POST https://api.kapso.ai/meta/whatsapp/v24.0/{phone_number_id}/messages
  Header: X-API-Key

  Maneja:
  - Teléfonos de 8 a 15 dígitos, sin "+".
  - Mensajes vacíos o de más de 4096 caracteres.
  - Errores HTTP de Kapso.
  - Errores de red con un mensaje claro (HTTP 503 hacia la UI).

- src/app/api/whatsapp/send/route.ts
  Ruta POST autenticada.

  Flujo:
  1. Valida mismo origen (sameOrigin).
  2. Valida sesión y usuario activo (actor).
  3. Rate limit: 20 envíos cada 15 minutos por IP.
  4. Valida body: { contactId: UUID, text: 1..4096 }
  5. Busca el contacto y exige que tenga teléfono.
  6. Envía por Kapso.
  7. Registra auditoría: whatsapp.sent
  8. Devuelve { ok: true, messageId }

  Errores traducidos:
  - 409: el destinatario debe escribir primero (ventana de 24 h).
  - 429: Kapso limitó los envíos.
  - 503: falta configuración o Kapso rechazó la autenticación.
  - 502: fallo genérico de envío.

- scripts/send-whatsapp.ts
  Envío de prueba por consola, sin usar la UI.

  Uso:
    npm run whatsapp:test
    npm run whatsapp:test -- --dry-run
    npm run whatsapp:test -- --text "Mensaje de prueba"
    npm run whatsapp:test -- --to 541167062068 --text "Mensaje de prueba"

- RESUMEN-WHATSAPP-KAPSO.txt
  Este archivo.

7. LIMITACIONES ACTUALES
------------------------

A. PostgreSQL local no está disponible.
   Error: ECONNREFUSED en 127.0.0.1:5432
   Sin base de datos no se puede cargar la app ni probar la ruta completa.

B. node_modules está instalado para Windows (win32-x64).
   El entorno de esta sesión es Linux/WSL.
   Por eso Next y esbuild no pueden ejecutarse desde acá.
   npm test falla por el binario de esbuild de otra plataforma,
   no por el código de WhatsApp.

   Para probar la UI: levantar PostgreSQL y ejecutar la app desde Windows.

C. Ventana de 24 horas de Meta.
   WhatsApp solo permite mensajes libres si el destinatario escribió
   al número en las últimas 24 horas.
   Fuera de esa ventana, Meta responde HTTP 422:
   "Cannot send non-template messages outside the 24-hour window".

D. Sandbox de Kapso.
   - Solo permite enviar al número autorizado.
   - El destinatario debe escribir primero al +56 9 2040 3095.
   - No permite listar ni usar plantillas.
   - Las comprobaciones de salud del número aparecen como no saludables
     porque el sandbox no soporta los chequeos de Meta.

E. Producción.
   Todavía no hay un número productivo conectado.
   El setup de producción quedó pendiente.
   Para enviar mensajes en frío hace falta:
   - Conectar una línea productiva.
   - Crear una plantilla.
   - Que Meta la apruebe.
   - Enviar con type: "template" en lugar de type: "text".


8. CÓMO PROBAR CUANDO LA BASE ESTÉ ARRIBA
-----------------------------------------

1. Iniciar PostgreSQL.
2. Ejecutar migraciones si hace falta:
     npm run migrate
3. Levantar la app:
     npm run dev
4. Entrar al CRM con un usuario administrador o agente.
5. Ir a Contactos.
6. Verificar que el contacto tenga teléfono.
7. Presionar "WhatsApp".
8. Escribir un mensaje y enviar.
9. Resultado esperado:
   - Toast: "Mensaje enviado por WhatsApp."
   - Registro de auditoría whatsapp.sent.

Para que el envío real funcione en el sandbox:
- El destinatario debe ser 541167062068.
- Primero debe escribir al +56 9 2040 3095.
- La ventana de 24 horas debe estar abierta.
